# 2026-06-16

## Work done: Remote sync status column

Added a per-project **Remote status** column to the table view of
`project_indexer.py`, showing how each project's local git branch compares to its
remote tracking branch.

### Changes
- **`project_indexer.py`**
  - New `_run_git()` helper — runs `git -C <dir> ...`, collapses all failures
    (missing git, non-zero exit, timeout) to `(False, '')`. Timeouts:
    `GIT_QUERY_TIMEOUT=5s`, `GIT_FETCH_TIMEOUT=60s`.
  - New `get_git_status(dir, do_fetch=False)` — detects repo → optional fetch →
    branch → upstream → `git rev-list --left-right --count @{u}...HEAD`. Returns
    `{state, branch, upstream, ahead, behind}`; states: `not_repo`, `error`,
    `detached`, `no_remote`, `up_to_date`, `ahead`, `behind`, `diverged`.
  - New `collect_git_statuses()` — concurrent (`ThreadPoolExecutor`, ≤16 workers).
  - New `git_status_badge()` — maps status → `(css_state, label)` with counts.
  - `generate_html()` — added `<th>Remote status</th>`, a `col-status` badge cell,
    `data-status` on rows, bumped empty-state `colspan` 3→4, added status CSS vars
    (dark + light) and `.status-badge` rules using `color-mix()`.
  - `main()` — added `--fetch` flag; computes git status fresh **after**
    `save_cache()` and attaches `entry['git']` in-memory only (cache stays
    README-only, so status never goes stale).

### Key decisions
- Git status is **never persisted** — recomputed every run (changes independently
  of README mtime/size that the cache tracks).
- Default = fast offline compare vs `@{upstream}`; `--fetch` = network fetch first.
- Status reflects the git repo *containing* each project dir.

### Testing
- `tests/test_git_status.py` (19 tests, all passing) — builds real repos with a
  local bare repo as the remote; fully offline incl. the fetch path.
- Added `pyproject.toml` (uv, `package = false`, pytest, `pythonpath=["."]`).
- Browser-verified the rendered table in Playwright (badges + layout correct).

### New files

## Work done: Fix horizontal scrollbar in table view

The table view rendered a horizontal scrollbar; the **Remote status** column was
pushed off the right edge of the viewport.

### Root cause
Default `table-layout: auto` sizes columns to their content's min-content width.
The `.col-path` cell holds a single space-free path (e.g.
`experiments/SDL_shadercross/external/DirectXShaderCompiler/lib/Target`) in a
monospace font with no wrapping rule, so its min-content width was huge — the sum
of column minimums exceeded the `1200px` `.container`, and the wrapper's
`overflow-x: auto` drew the scrollbar. The card view was unaffected (path lives
in a freely-wrapping block `<p>`).

### Changes — `project_indexer.py` (CSS only, in `generate_html()`)
- `.col-path` — added `overflow-wrap: anywhere;` so long paths wrap. Chose
  `anywhere` over `break-word` because only `anywhere` shrinks the cell's
  intrinsic min-content width, which is what actually lets the table fit.
- `.col-summary` — added `overflow-wrap: anywhere;` as a guard against a stray
  long token (e.g. a URL) in a description.
- Intentionally kept `table-layout: auto` (preserves the `.col-status`
  `width:1%` + `nowrap` shrink-to-fit trick) and the wrapper's `overflow-x: auto`
  (graceful fallback on very narrow viewports).

### Testing
- `uv run pytest` — 19 tests still pass.
- Playwright-verified at 1280px against a synthetic tree reproducing the deep
  DirectXShaderCompiler path: `wrapper.scrollWidth === clientWidth` (no overflow),
  the long path wraps to 3 lines, the long-URL description wraps, and the Remote
  status column is fully visible.
